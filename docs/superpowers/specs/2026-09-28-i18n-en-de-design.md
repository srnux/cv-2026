# Multilingual site: en-GB and de-DE

Date: 2026-09-28
Status: approved design, awaiting spec review

## Goal

The whole site is available in British English and German. English stays the default at `/`. Visitors whose browser prefers German are offered the German version, never switched automatically, and an explicit choice is remembered.

The German version has to be real, crawlable HTML for the same reason the home page is prerendered today: German ATS parsers, LLM screeners and search engines must read German content without executing JavaScript.

## Decisions

| Topic | Decision |
|---|---|
| Detection | Browser language only: an entry of `navigator.languages` starting with `de`. No time zone check, no IP geolocation, no third party. |
| Behaviour on detection | Offer only. Nothing redirects until the visitor clicks. |
| Remembered choice | Stored after an explicit click. A stored `de` redirects later visits of English pages to their German equivalent; a stored `en` suppresses the offer. |
| Default | English at `/`. German under `/de/`. |
| Articles | Optional German translation per article. Without one, the German route shows the English body inside German chrome. |
| dev.to | Only English articles are cross-posted. German articles are not. |
| Legal pages | Impressum and Datenschutz get English versions, translated as closely as possible. No "German version prevails" disclaimer. |
| i18n mechanism | Typed dictionaries, no i18n library. |
| Sitemap | Generated by the article generator instead of maintained by hand. |

Rejected: `react-i18next` (runtime lookup, silent missing keys, weight not justified for two languages of static prose); single URL with runtime switching (no crawlable German page).

## URL map

| URL | Content |
|---|---|
| `/` | Home, en-GB, prerendered |
| `/de/` | Home, de-DE, prerendered |
| `/writing/<slug>/` | Article, English |
| `/de/writing/<slug>/` | Article, German if `content/articles/<slug>.de.md` exists; otherwise English body with German chrome |
| `/impressum.html`, `/datenschutz.html` | German legal pages, URLs unchanged |
| `/legal-notice.html`, `/privacy.html` | English legal pages, new |
| `/cv-luka-engels-en.html`, `/cv-luka-engels-de.html` | Unchanged |

Every page that has a counterpart in the other language declares both with `<link rel="alternate" hreflang="en-GB|de-DE">`, plus `x-default` pointing at the English one. Each page's canonical is itself.

## Home page

### Dictionaries

- `src/i18n/types.ts` declares `Lang = 'en' | 'de'` and the `Messages` type: every user-visible string of every component, plus structured content (experience roles, skill groups, education, projects), plus head metadata (title, description, OG/Twitter texts, `og:locale`, JSON-LD `description`, `jobTitle`, `seeks.name`).
- `src/i18n/en.ts` and `src/i18n/de.ts` each export a `Messages` value. A missing or misspelt key in either fails `pnpm typecheck`.
- The current English copy moves verbatim from the components into `en.ts`. No wording changes in English.
- A React context (`LangProvider`, `useMessages()`, `useLang()`) provides the active language and dictionary. Components read from it and keep no copy of their own.
- `src/i18n/paths.ts` holds pure functions: `langFromPath(pathname)`, `counterpartPath(pathname, targetLang)` and the list of paths that have a German equivalent.

### Language resolution

- Server: `render(lang)` in `entry-server.tsx` takes the language as an argument.
- Client: `index.tsx` resolves it with `langFromPath(location.pathname)` before hydrating. The same URL always yields the same language on both sides, so hydration matches.
- `pnpm dev`: Vite's SPA fallback serves `index.html` for `/de/`, so both languages work in dev with no extra configuration.

### Head metadata

- `index.html` keeps its English head so dev and `build:client` still work unchanged.
- `scripts/prerender.ts` renders the app twice. For German it rewrites the head of a copy of `dist/index.html` from the German dictionary: `<html lang>`, title, description, canonical, OG and Twitter tags, `og:locale`, and the language-dependent JSON-LD fields. It then writes `dist/de/index.html`.
- Both outputs get the `hreflang` alternates.
- The existing guard stays: if `<div id="root"></div>` is missing, prerender throws. It also throws if any head element it has to rewrite is not found, rather than shipping German content under an English title.

### German copy

- Drafted from the existing `DE` content model in `scripts/build-cv-pages.ts` wherever the site and the CV say the same thing; everything else translated from the English site copy.
- Editorial rules apply unchanged: no em or en dashes in prose, collective voice ("wir", "unser Team") for delivery claims, first person singular only for title, leadership scope, what he is looking for and working style.
- Headline: `Lead Software Engineer · Agentic AI & LLM-Plattformen · TypeScript / AWS`, matching the German CV.
- Citizenship stated; permanent, fully remote employment only; no freelance or contract wording; no claim of immediate availability.
- The German copy needs a read by a native speaker before it goes live.

## Offer bar, switcher, stored choice

### Stored choice

- One key: `localStorage['lang']`, value `'en'` or `'de'`.
- Written only on an explicit click (offer bar button or language switcher). Never written on detection alone.
- Every read and write is wrapped in `try/catch`; a throwing or empty store means "no choice made".

### Redirect for a stored `de`

- A small inline script in the `<head>` of every English page that has a German counterpart (home and articles). If the stored value is `'de'`, it calls `location.replace(counterpartPath(...))` before the body renders, so English never flashes.
- For an article without a German translation, the German route still exists (English body, German chrome), so the redirect target always exists.
- No reverse redirect. English is the default; a stored `en` only suppresses the offer.
- Crawlers do not execute it and have no stored choice, so they always read the page they requested.

### Offer bar

- Shown on English home and article pages only, when there is no stored choice and `navigator.languages` has an entry starting with `de`.
- Mounted from an effect on the home page and from a small inline script on the static article pages. Never present in the prerendered or generated HTML.
- Slim bar above the header, black and white to match the site: "Diese Seite gibt es auch auf Deutsch." with "Auf Deutsch lesen" and "English".
  - "Auf Deutsch lesen" stores `de` and navigates to the German counterpart.
  - "English" stores `en` and hides the bar.
- Not shown on legal or CV pages.

### Language switcher

- `EN / DE` in the header navigation and the mobile menu, the active language marked.
- Real `<a href>` links to the counterpart page, so crawlers follow them. A click also stores the chosen language, so choosing EN on a German page cancels the redirect.
- Article pages and all four legal pages get the same switcher as plain HTML links. Legal pages link Impressum to Legal notice and Datenschutz to Privacy policy.

### In-page links

- Header links to the CV of the active language (`-de.html` on the German site).
- Footer links to the legal pages of the active language.
- The contact form's labels, validation messages, success and error states and the `mailto:` fallback subject and body are translated.

## Articles

- Source: `content/articles/<slug>.md` (English, required) and optionally `content/articles/<slug>.de.md` (German). The German file has its own `title`, `description` and `tags`. `date` and `coverImage` fall back to the English file when omitted. The slug is shared, so the rule "never rename a published article's file" covers both.
- A `.de.md` without an English sibling fails the build.
- `pnpm articles` generates:
  - `public/writing/<slug>/index.html` (English)
  - `public/de/writing/<slug>/index.html`: German, or English body with German chrome. In the fallback case the article body carries `lang="en"`, a short German note says the article is only available in English, and its canonical points at the English page with no `hreflang` pair, because the content is not translated.
  - `content/devto/<slug>.md` from the English file only, as today.
  - `src/content/articles.json` as `{ "en": ArticleMeta[], "de": ArticleMeta[] }`. German entries carry `lang: 'en' | 'de'` so the German listing marks English-only articles ("Artikel auf Englisch").
  - `public/sitemap.xml`, see below.
- German page chrome: navigation, date formatted `de-DE`, button labels, back link to `/de/#writing`.
- `Writing.tsx` keeps declaring its own `Article` type, extended with `lang`, in step with `ArticleMeta`.

## Sitemap and llms.txt

- `public/sitemap.xml` becomes generated by `pnpm articles`: home in both languages, CV pages, all article URLs in both languages, the four legal pages, with `xhtml:link` `hreflang` pairs where a translation exists. Hand-editing is no longer the workflow; CLAUDE.md is updated to say so.
- `public/llms.txt` stays hand-maintained and gains the German home URL and German article URLs.

## Legal pages

- `public/legal-notice.html` and `public/privacy.html`: English translations of `impressum.html` and `datenschutz.html`, as close to the German text as possible. Same sections, same order, same facts; no paraphrasing or simplification. German statutes keep their German names with the English abbreviation where one exists, for example "DSGVO (GDPR)", "§ 5 DDG".
- The Datenschutz and its translation gain one paragraph on the language preference stored in `localStorage`: what is stored, that it happens only on an explicit click, that nothing is transmitted, and that it is strictly necessary to provide the requested function (§ 25 Abs. 2 Nr. 2 TDDDG), so no consent is required.
- Both English pages carry `lang="en"` and the language switcher.

## Testing

- Add Vitest as a dev dependency, with a `pnpm test` script, and run it in CI before the build.
- Unit tests:
  - `langFromPath` and `counterpartPath` for home, articles with and without translation, trailing slashes, hash and query.
  - Detection: `de`, `de-AT`, `de-CH`, `en-GB`, empty list.
  - Stored choice: read/write, with storage absent and with storage that throws.
- Build output test (runs against `dist/` after `pnpm build`):
  - `dist/index.html` has `lang="en"`, English title, canonical `/`, `hreflang` to `/de/`.
  - `dist/de/index.html` has `lang="de"`, German title and description, canonical `/de/`, `hreflang` back, German content in `#root`, and no offer bar markup.
  - Both languages have prerendered content, not an empty root.
- Typecheck enforces dictionary completeness.
- Manual check in the browser with the browser language set to German: offer appears, both buttons behave, the choice survives a reload, the switcher overrides it, and there is no flash of English with a stored `de`.

## Out of scope

- Languages beyond en-GB and de-DE.
- German dev.to cross-posts.
- Translating the existing article. The mechanism is built; translations come per article.
- Changes to the CV pages beyond links pointing at them.
